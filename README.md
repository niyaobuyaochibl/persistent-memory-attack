# Persistent Memory Is an Attack Surface

Code for *Persistent Memory Is an Attack Surface: Early-Exposure Manipulation of LLM
Recommender Agents and an Exposure-Residualized Defense* (submitted to ACM TIST).

An LLM recommender agent stores each user's clicks in memory and re-reads them at
every turn. An attacker who controls what the user is shown during the first few
rounds can therefore plant a lasting preference. This repository contains the paired
counterfactual environment that measures the effect, the memory policies compared in
the paper (raw logs, recency truncation, exposure-aware memory, LLM fact memory,
mem0, and ERSM with its ablations), and the scripts that produce every table.

## Layout

| Path | Contents |
| --- | --- |
| `stickyrec/` | environment, memory policies, LLM backends, analysis |
| `scripts/` | data preparation, config generation, experiment drivers, aggregation, tables |
| `configs/` | the exact configs behind each experiment (`revision/`: main study, ablations, stress tests, mem0; `llama_v1/`, `qwen14b_v1/`: other open-weight agents; `kuairec/`; `api/`: OpenRouter models; `plan/`: GPT models) |
| `data/splits/` | split corrections for MovieLens-1M (see below) |
| `results/summary/` | aggregated results (lifts, bootstrap intervals, Holm-corrected tests) behind the paper's tables |
| `figures/` | scripts that draw Figures 1–3 and the cross-model table from `results/summary/` |
| `tests/` | unit tests |

## Setup

```bash
pip install -e '.[llm]' vllm mem0ai sentence-transformers faiss-cpu
python -m unittest discover -s tests
```

Everything runs from this directory and expects the processed datasets in
`../niche_user_study/data`.

## Data

The datasets are not redistributed; download them from their providers and run
`scripts/prepare_data.py`, which writes the splits and MiniLM item embeddings.

- **MovieLens-1M** ([GroupLens](https://grouplens.org/datasets/movielens/1m/)): unzip
  `ml-1m.zip`, then

  ```bash
  python scripts/prepare_data.py ml1m --raw ml-1m --data-root ../niche_user_study/data
  mkdir -p data/raw/ml-1m && cp ml-1m/movies.dat data/raw/ml-1m/
  ```

  Movies with at least 5 ratings; each user's ratings sorted by time and split
  80/10/10. The paper's split broke timestamp ties in an unrecorded order, so
  `data/splits/ml1m_split_overrides.csv` lists the 1% of (user, movie) pairs whose
  split differs from a stable sort. With it the script reproduces the paper's split
  row for row.

- **Amazon CDs and Vinyl** ([Amazon Reviews 2023](https://amazon-reviews-2023.github.io/)):
  download `benchmark/5core/timestamp/CDs_and_Vinyl.{train,valid,test}.csv.gz` and
  `raw/meta_categories/meta_CDs_and_Vinyl.jsonl.gz` into one directory that keeps
  these subpaths, then

  ```bash
  python scripts/prepare_data.py cds --raw amazon_2023 --data-root ../niche_user_study/data
  ```

- **KuaiRec 2.0** ([KuaiRec](https://kuairec.com/)):

  ```bash
  python scripts/prepare_kuairec.py --raw KuaiRec/data --data-root ../niche_user_study/data \
    --embedder sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2
  ```

## Running the experiments

Every experiment is a set of configs generated by `scripts/make_revision_configs.py`
and run by `scripts/run_revision_suite.py`, which skips runs whose outputs already
exist. Results land in `results/revision/<config>/`; `scripts/aggregate_revision.py`
computes the paired lifts, user-clustered bootstrap intervals and Holm-corrected tests
in `results/revision_summary/all.csv`, and `scripts/make_extended_tables.py` writes the
LaTeX tables.

```bash
export PYTHONPATH=. MEM0_TELEMETRY=False

# main study, ablations, stress tests (Qwen3-8B-AWQ, local vLLM)
python scripts/make_revision_configs.py --out configs/revision
python scripts/run_revision_suite.py --backend vllm
# mem0 runs talk to an OpenAI-compatible vLLM server on port 8000
bash scripts/start_vllm_server.sh
python scripts/run_revision_suite.py --backend openai --configs configs/revision

# other open-weight agents
python scripts/make_revision_configs.py --set model --tag llama_v1 \
  --model-name meta-llama/Llama-3.1-8B-Instruct --out configs/llama_v1
python scripts/run_revision_suite.py --backend vllm --configs configs/llama_v1

# KuaiRec logged feedback
python scripts/make_revision_configs.py --set kuairec --out configs/kuairec
python scripts/run_revision_suite.py --backend vllm --configs configs/kuairec

python scripts/aggregate_revision.py
python scripts/make_extended_tables.py
```

To summarize one group of runs, point `aggregate_revision.py --results DIR --out DIR`
at a directory that holds (or symlinks) only those run directories; the files in
`results/summary/` were produced this way.

`scripts/run_all.sh` and `scripts/run_extended.sh` chain the vLLM steps on a GPU
machine; set `ROOT` to the directory that holds this repository, the
`niche_user_study` data, a `venv`, and downloaded models.
`scripts/smoke_revision.py` runs every config for a few users with a stub model and
needs no GPU.

**Hosted models through OpenRouter** (Claude-Haiku-5.5, DeepSeek-v4.1-flash,
Qwen3.8-27B; temperature 0, reasoning disabled, pinned provider and precision):

```powershell
$env:OPENROUTER_API_KEY = "..."
.\scripts\run_api.ps1 pilot     # 20 users, seed 42
.\scripts\run_api.ps1 full      # 200 users x 3 seeds
```

**GPT models through a ChatGPT plan** (`--backend chatgpt_plan`). This backend
imports a local `chatgpt_plan_api` client from `CHATGPT_PLAN_CLIENT_DIR` that is not
part of this repository. The plan route does not expose temperature, so responses are
sampled at the model default; each distinct prompt's first successful response is
cached in `results/plan_cache/<tag>.jsonl` and reused. `run_plan_full.ps1` waits out
quota limits and resumes from the cache. With an OpenAI API key, the same experiment
runs through the `openai` backend instead.

```powershell
.\scripts\run_plan.ps1 pilot gpt6luna
.\scripts\run_plan_full.ps1 gpt6luna 123
```

## Results

`results/summary/` holds the aggregated outputs used in the paper:
`revision_all.csv` (Qwen3-8B main study, ablations, stress tests, fact memory, mem0),
`extended_all.csv` (Llama-3.1-8B, Qwen3-14B, KuaiRec), and `hosted_all.csv` (OpenRouter
and GPT models). Each row is one experiment, metric and memory policy, with the mean,
95% user-clustered bootstrap interval, p-value, numbers of users, pairs and seeds,
and the Holm-corrected p-value where applicable.

## Figures

`figures/make_framework.py` draws the framework diagram (Figure 1);
`figures/make_results_figs.py` draws the cross-model lifts (Figure 2) and attacker
strength (Figure 3) and writes the cross-model table (`tab_models.tex`) from the CSVs
in `results/summary/`. Neither needs a GPU or the datasets.

```bash
pip install -e '.[figures]'
python figures/make_framework.py
python figures/make_results_figs.py
```
